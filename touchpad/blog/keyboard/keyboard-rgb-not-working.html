Keyboard RGB Stopped Working or Flickering? Fix Guide

Updated September 2026 · 6 min read

RGB problems feel like hardware failures and usually are not. LEDs are among the most reliable components in a keyboard — they routinely outlast the switches. When lighting misbehaves, the cause is almost always power delivery, software, or a setting, in roughly that order of likelihood.

The useful first question is whether the keyboard still types correctly. Run it through the keyboard test before you do anything else. Lighting that fails while typing stays perfect is a very different problem from lighting and typing failing together — the second points at the USB connection, and that changes everything below.

Start with the shortcut you pressed by accident

Before opening any software: nearly every keyboard has a brightness shortcut, and nearly every one of them is two keys apart from something you use constantly.

Look for Fn plus the up or down arrow, or Fn plus a key with a small sun or brightness icon — often on the F-row, or on Page Up and Page Down. Press the "increase" direction five or six times.

RGB has brightness steps, and the lowest step is usually off, not dim. So a keyboard whose lighting has "died" has very often just been stepped down to zero by someone reaching for Page Down. It costs ten seconds to rule out and it is the answer more often than anything else here.

While you are there, check the effect too — many boards have a "reactive" mode where keys light only on press, and an idle keyboard in that mode looks broken.

If the lighting is flickering

Flickering is a power symptom, near enough always. A full RGB keyboard at maximum brightness can draw close to the 500mA a USB 2.0 port is specified to deliver, and the LEDs are the first thing to misbehave when supply sags.

Things that cause it, in the order worth testing:

  • An unpowered USB hub. The most common cause by a distance. Plug the keyboard directly into the computer instead. If the flicker stops, the hub was the problem — either use a powered hub or keep the keyboard on a direct port.
  • A front-panel port. Front and top case ports run through an internal header and a length of thin cable, and they sag under load in a way rear ports do not. Move to a rear port, which connects to the motherboard directly.
  • The cable. Detachable USB-C cables on keyboards are a weak point, and a partly damaged cable delivers enough power to enumerate but not enough to run LEDs steadily. Swap it for a known-good one — this is worth doing early because it is free.
  • Two high-draw devices on one controller. A keyboard and an RGB mouse sharing a port cluster can exceed the controller's budget. Move one somewhere else.

If you have a keyboard with a second "power" USB plug — some older full-RGB boards ship with a split cable — both need to be connected. People plug in one and wonder why the lighting is unstable.

If a section has gone dark

A whole block of keys dark while the rest works is one of the few genuinely hardware-shaped RGB faults, but check the boring explanation first: many lighting effects and custom profiles deliberately leave zones unlit. Cycle through the built-in effects with the Fn shortcut. If every effect shows the same dark block, it is not the effect.

After that, the likely cause is a failed connection on that part of the PCB — often after a liquid spill, or a knock, or a case that was reassembled with a ribbon cable pinched. On a board with a detachable plate assembly, reseating the internal ribbon connector sometimes brings a dead zone back.

A single dead key LED, as opposed to a zone, does happen and is genuinely a dead LED. On a hot-swap board with per-switch LEDs mounted in the switch (rather than the PCB), swapping the switch swaps the LED. On a board with PCB-mounted LEDs, it is a soldering job for one component.

If lighting quit entirely and typing is fine

Work through these in order:

  1. Brightness shortcut. Covered above, but worth repeating because people skip it.
  2. Unplug for thirty seconds. Keyboard controllers hold lighting state in volatile memory and can get stuck. A real power cycle — not a reboot, which often keeps USB powered — clears it. On wireless boards, power off and remove the dongle too.
  3. Check the software is running. iCUE, Synapse, GHUB, Armoury Crate and friends push lighting to the keyboard. If the service has crashed or failed to start after an update, lighting can fall to off rather than to the onboard default. Restart the application, then restart its background service.
  4. Reinstall that software. Vendor lighting suites break themselves on update with some regularity. A clean reinstall — uninstall, reboot, install fresh — fixes a surprising proportion of "my RGB died" reports.
  5. Factory reset the keyboard. Usually holding Esc while plugging in, or a documented Fn combination. This clears onboard profiles, including a corrupted lighting profile.
  6. Update the firmware. Last, not first. Firmware updates fix real lighting bugs, but a failed flash creates a much bigger problem than the one you started with. Make sure the keyboard is on a direct rear USB port before you flash anything.

The software conflict nobody expects

Running two lighting applications at once causes chaos: each tries to own the device, they fight over it, and the symptom is flickering, colour snapping between profiles, or lighting that works until the other app wakes up.

This happens more than you would think — OpenRGB alongside a vendor suite, SignalRGB alongside iCUE, or motherboard lighting software that has claimed the keyboard as a generic device. Pick one and uninstall the others properly.

When lighting and typing both fail

That is not an RGB problem. Everything stopping at once points to the USB connection, the cable, or the controller — see keyboard disconnecting randomly for the connection-side checks, and keyboard not working for the broader ones.

FAQ

Can RGB lighting drain a laptop battery noticeably?

Yes, more than people expect. A full-brightness RGB keyboard can pull a couple of watts, which on a thin-and-light laptop is a real fraction of idle draw.

Most laptops dim or disable keyboard lighting on battery by design, which is also why lighting "stops working" the moment you unplug the charger. That is intended behaviour, not a fault.

Why does my lighting reset every time I restart?

Because the profile is being stored in the software rather than on the keyboard, and the software loads after Windows does. There is a gap where the board shows its onboard default.

If your keyboard supports onboard memory, save the profile to the board itself. Then it applies the instant it gets power, with no software involved.

Is a dead LED worth repairing?

On a hot-swap board with LEDs in the switches, yes — swapping the switch swaps the LED and costs pence.

On a board with LEDs soldered to the PCB, it is a fine soldering job on a small surface-mount component. Worth it only if you enjoy that sort of thing or the board is expensive.

Does turning RGB off make the keyboard perform better?

Not in any way you can measure. Lighting is handled separately from key scanning, and switching it off does not reduce input latency or improve polling.

It does reduce power draw, which matters on a laptop or on a marginal USB port — and that is the one case where turning it off genuinely helps.
